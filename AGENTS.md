# Working rules for coding agents in this repo

1. **`design.md` is the source of truth** for architecture, schema, config shapes and component boundaries. Read it before changing anything.
2. **Design changes travel with code.** Any change to a component's behaviour, a table or view, a config file's shape, or a design decision updates `design.md` *and* appends a dated entry to its decision log (date, decision, why, what it replaced) in the same commit as the code.
3. **Log tables are append-only.** `runs`, `observations`, `links`, `trips`, `checks`, `annotations` are only ever INSERTed into (the one exception: closing out an open `runs` row, see `design.md`). Triggers enforce this; never drop or weaken them. Entities (`places`, `units`, `listings`, `operators`) are derived views. Never add a table that holds a second copy of a fact.
4. **Gather wide, filter late.** Intake never narrows collection by a goal's criteria. Goals are filters over stored data.
5. **Unknown never rejects.** A filter whose input is missing returns `needs_check` and names the missing field. Filters report, they never delete.
6. **No direct scraping of listing sites from this machine.** Every listing source, including property and operator websites, goes through Apify actors. Non-listing reference data (OpenStreetMap, Caltrain timetable) may be fetched directly. Exception (2026-11-25, user's decision): the image files at photo and floor-plan URLs our sources already gave us may be downloaded directly (`aptf-media fetch`); that is image files only, never pages.
7. **Never contact a landlord**, submit a form, apply, or send a message on the user's behalf.
8. **If a source returns bad, empty or suspicious data, stop and tell the user.** Do not work around it quietly.
9. **When blocked, name the blocker; don't detour.** If something is blocked (a broken actor, a missing permission or key, a plan limit, a site that changed), stop and state the blocker plainly: what failed, the exact error, and what would unblock it. Do not build workarounds, alternative scrapers or exploratory probes unless the user asks for that specific path. Detours waste time, tokens and money.
10. **Secrets** (`APIFY_TOKEN`, `GOOGLE_MAPS_API_KEY`) come from `.env`, never from code or commits. Respect the per-run spend cap.
11. **The `commute` package stays independent:** no imports from the rest of the project, no knowledge of apartments, goals or the main schema.
12. Run `env -u PYTHONPATH uv run pytest` before committing (this machine's ROS `PYTHONPATH` otherwise injects broken pytest plugins). Commit after each feature or bug fix (small commits), each with its `design.md` decision-log entry when behaviour or design changed.
13. **Keep the user in the loop.** Post a short status line before and after every long step (a build, a scrape, an LLM pass, a deploy): what is running, where, and the expected cost. Never go quiet for long stretches. Report what each step produced with **real examples from the results** (rows, extracted values, accepted and rejected sites), not only counts. For anything new you build, show its output on real data before calling it done.
14. **The live system runs on the NixOS box** (`~/Documents/apartment-finder`, systemd user service `aptfinder.service`). Its database is the live one; deploy with push, pull there, restart the service. Snapshot the database before any bulk append (reparse, extract).
